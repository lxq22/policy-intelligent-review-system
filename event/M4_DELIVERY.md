# M4 解析与审查流程交付说明

## 交付范围

M4 已把原型从基础制度管理推进到真实解析与审查输入流程：

1. 正式制度可上传新版本、重新解析并展示条款；临时待审文件独立上传，不进入制度库。
2. 支持 `.docx` 与带可选文字的 `.pdf`，保留条款编号、章路径、正文和段落顺序。
3. 用户可指定一个或多个待审条款及审查维度。
4. 制度冲突维度从当前制度关系覆盖的制度中，使用关键词与 256 维本地向量进行 RRF 混合召回，由用户确认候选条款。
5. 保存制度/临时文件、条款、维度和候选的不可变快照；每次审查独立记录，编号格式为“待审制度名称-YYYYMMDD-NN”，不设置任务状态。

## 明确边界

- 当前解析对象仅为 Word 正文段落和 PDF 可选文字。
- 不解析 Word 表格，不提供扫描 PDF OCR，不使用页码作为证据位置。
- M4 不调用外部大模型，不生成四维问题、证据判断、修改建议、报告或人工处理记录；这些属于 M5。
- 临时文件不会出现在制度库中，M4 不自动删除临时文件。

## 固定测试资料

`制度审查测试数据集/生成文件/` 中提供 4 组、共 8 个固定文件，每组同时包含 DOCX 和 PDF：

- `待审查_章程配套制度_含上下级口径冲突`
- `待审查_综合审查样例`
- `待审查_资金与关联交易_含关联冲突`
- `待审查_重大事项管理_含流程冲突`

文件由 `制度审查测试数据集/生成测试文件.py` 根据同目录说明与制度资料生成，可重复生成；测试会核对同组 DOCX/PDF 的条款编号和正文一致性。

## 运行

在 `event/` 目录执行：

```bash
docker compose up --build -d
docker compose exec api alembic upgrade head
```

- 页面：<http://localhost:8080>
- API 文档：<http://localhost:8000/docs>
- 健康检查：<http://localhost:8000/health>

演示账号与初始密码见 `README.md`。

# 制度上传与临时文件条款预览设计

## 目标

解决以下三个已确认的问题：

1. “制度库 → 新增制度”中的制度文件目前只是文本输入框，没有执行真实上传。
2. “发起审查 → 临时上传待审文件”中，已选择文件显示在上传框外，状态不明显，也不便于更换或删除。
3. 临时文件解析完成后，用户在进入条款选择前看不到明确的解析结果预览。

本次改动只调整制度新增、临时文件上传和条款预览流程，不实现智能分析与审查报告生成。

## 已确认的业务规则

- 新增制度时必须上传制度文件；未选择文件不能保存制度。
- 新增制度支持 `.docx` 和普通文字 PDF。
- 不支持 `.doc`、扫描 PDF、图片或需要 OCR 的文件。
- 新增制度成功后应已完成初始版本上传和条款解析，并进入制度详情页查看解析结果。
- 编辑已有制度信息时不要求重新上传文件。
- 已有制度的新版本继续从制度详情页上传。
- 临时文件不会进入正式制度库。
- 临时文件解析成功后，用户先查看条款预览，再进入“指定条款”步骤选择本次审查条款。

## 方案选择

### 新增制度

采用“制度信息、初始文件和初始版本一次提交”的方案，而不是由前端先创建空制度、再调用版本上传接口。

原因：制度文件已经被确认是新增制度的必填项。一次提交能够避免文件上传或解析失败后，制度库中残留只有制度信息、没有有效文件的正式制度。

后端新增面向“新增制度”的 multipart 接口，接收制度字段和文件。接口依次完成：

1. 校验用户上传权限、制度字段和文件类型。
2. 保存文件。
3. 创建制度及其初始版本。
4. 解析文件并保存条款。
5. 写入“新增制度”操作记录。
6. 返回包含解析状态、版本和条款信息的制度数据。

任何步骤失败时，本次新增不应留下可见的残缺制度。文件系统中已经写入但事务失败的文件也应清理。

现有的制度信息编辑接口和制度版本上传接口保持不变。

### 临时文件上传

选择文件后立即调用现有临时文件上传与解析能力，不再等用户点击“下一步”才上传。

上传组件分为以下状态：

- 未选择：显示拖拽区域和“点击选择”。
- 待上传／解析中：在上传框内部显示文件卡片、文件名、大小和加载状态，并禁止重复操作。
- 解析成功：显示文件卡片、成功状态、解析条款数以及删除／更换入口。
- 解析失败：保留清晰的失败原因，允许删除并重新选择文件。

选择新文件或删除当前文件时，必须同步清空旧的临时文件对象、已选条款、候选条款和相关页面状态，防止旧解析结果进入新审查。

## 页面设计

### 制度库的“新增制度”弹窗

- 将“制度文件”文本输入框替换为横跨整行的拖拽上传区域。
- 文件选择成功后，在上传区域内部展示文件卡片：文件图标、名称、大小、格式和删除／更换操作。
- 底部主按钮名称改为“保存并解析”。
- 没有选择文件时点击主按钮，提示“请上传制度文件”，不发送新增请求。
- 提交期间显示加载状态并防止重复提交。
- 成功后关闭弹窗并进入新制度详情页；详情页的“解析条款”标签应能看到初始版本解析出的条款。

### 发起审查的“临时上传待审文件”区域

- 保留拖拽上传形式。
- 选中文件后，拖拽区域自身切换为文件卡片状态，不再在上传框下方另外输出文件名。
- 文件卡片显示文件名、大小、解析状态和删除／更换操作。
- 对比制度选择仍位于临时文件区域内，不改变其业务含义。

### 临时文件条款预览

解析成功后，在“审查来源”步骤的上传区域下方立即显示解析结果：

- 顶部显示“解析成功，共 N 条”。
- 按原文顺序展示条款编号、标题和证据位置。
- 条款正文默认折叠，用户可逐条展开查看全文。
- 明确提示：这里用于确认解析结果；进入下一步后再选择实际需要审查的条款。
- 若解析结果不正确，用户可以删除文件并重新上传。

点击“下一步”后进入现有“指定条款”步骤。该步骤继续使用复选框选择一个或多个条款，不默认整份审查。

## 数据与状态流

### 新增制度

`填写制度信息 → 选择制度文件 → 保存并解析 → 后端事务创建制度和初始版本 → 解析条款 → 返回新制度 → 进入制度详情`

### 临时审查

`选择临时文件 → 自动上传和解析 → 显示文件状态及条款预览 → 用户确认 → 下一步 → 勾选待审条款`

切换审查来源、删除文件或更换文件时，清理以下状态：

- 已上传临时文件及其条款
- 已选待审条款
- 已选冲突候选条款
- 上一次候选检索结果

## 错误处理

- 未上传制度文件：阻止保存并给出明确提示。
- 文件格式不支持：在上传区域显示后端返回的具体原因。
- 扫描 PDF 或空文档：提示无法提取可审查文字，允许更换文件。
- 文件上传失败：新增制度不进入正式列表；临时上传保留失败状态并允许重试。
- 条款解析失败：不允许进入“指定条款”步骤。
- 重复点击：上传或保存期间禁用相关按钮。

## 测试与页面验证

自动测试至少覆盖：

1. 新增制度未选择文件时不会提交。
2. 新增制度 multipart 请求同时包含制度信息和文件。
3. 新增成功后制度包含初始版本、真实文件名和解析条款。
4. 新增过程失败时不留下可见的残缺制度。
5. 临时文件选择后立即触发上传解析。
6. 文件卡片在上传框内部显示名称、大小和解析状态。
7. 临时文件解析成功后在当前步骤显示条款总数及条款预览。
8. 删除或更换文件会清空旧条款和选择状态。
9. 解析失败时不能进入下一步，并显示可理解的错误。

页面验证流程：

- `制度库 → 新增制度 → 选择文件 → 保存并解析 → 制度详情 → 解析条款`
- `发起审查 → 临时上传 → 文件卡片 → 条款预览 → 下一步 → 指定条款`

桌面视口必须检查上传区域、弹窗滚动、文件卡片、条款折叠和按钮状态；同时检查一个移动端视口，确保内容不重叠、不被裁切。页面运行期间不应出现相关控制台错误或框架错误遮罩。

## 非目标

- 本次不接入 DeepSeek、智谱或其他模型。
- 本次不生成真实审查问题或报告。
- 本次不增加 OCR、扫描件或图片解析。
- 本次不改变制度关系、候选条款检索和权限模型。

# M5 四维智能审查设计

## 要完成的功能

- 使用 GLM‑4.7 生成真实审查结果，不再使用固定模拟问题。
- 支持语义分歧、规则匹配、制度冲突、一致性四个维度。
- 按维度保存并展示问题，同一原文可以在不同维度分别产生问题。
- 证据不足时显示“证据不足，请人工判断”。
- 支持采纳修改建议、忽略、补充处理意见，并记录操作人和时间。
- 历史审查记录可以重新打开对应的真实报告。

## 审查方式

采用“本地规则＋GLM‑4.7”：

- 本地规则先识别明确问题，保证规则依据可追溯。
- GLM‑4.7 负责语义判断、冲突分析、判断说明、可能后果和修改建议。
- 模型只分析用户选择的条款和维度。
- 制度冲突只使用用户选择的候选条款。

四个维度的第一版范围：

- 语义分歧：检查“及时、适当、原则上”等模糊表达及其他明显歧义。
- 规则匹配：只检查文本结构、条款编号和行文规范。
- 制度冲突：检查引用错误、失效制度、规定冲突等问题。
- 一致性：检查术语、责任主体、数值、时限和制度信息是否前后一致。

不增加风险等级、模型置信度、视觉排版、表格、扫描件或 OCR。

## 技术实现

- 后端增加供应商中立的模型适配层，通过环境变量配置接口地址、API Key 和模型名称。
- 当前部署默认模型为 `glm-4.7`，调用智谱官方对话补全接口。
- 使用 JSON 结构化输出，并用 Pydantic 再次校验结果。
- 模型格式错误时自动纠正一次；仍失败则本次审查失败，不保存残缺报告。
- 审查过程通过 SSE 返回“正在分析、保存结果、完成或失败”。
- 审查问题、维度专属字段和处理历史存入 PostgreSQL。
- API Key 只放在本机 `.env`，禁止写入代码、日志和 Git。

## 页面流程

`选择条款和维度 → 开始审查 → 显示运行进度 → 审查成功 → 打开真实报告`

- 审查失败时显示明确原因，并允许重新发起。
- 报告不存在或编号错误时显示“报告不存在”，不能自动展示其他记录。
- 审查记录有真实结果时显示“查看报告”，没有结果时不展示假报告。

## 完成标准

- 四个维度都能生成、保存和查询真实问题。
- 每个维度使用自己的展示字段，只有制度冲突展示对比制度原文。
- 采纳、忽略和补充意见都能保存历史记录。
- 自动测试使用假模型，不消耗 API 额度。
- Docker、后端测试、前端测试和页面实际操作全部通过。
- 最后使用真实 GLM‑4.7 对测试数据完成一次联调。

## API Key

开发和自动测试阶段不需要真实 API Key。进入最终 GLM‑4.7 联调时，由用户将密钥写入本机 `.env`；密钥不得通过聊天、代码提交或截图公开。
